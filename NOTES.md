Lode Runner port semantics
=========================

Status and boundaries
---------------------

Faithful emulation covers core level gameplay from active level start through the committed Died or LevelCleared snapshot: movement, digging, guards, gold, holes, exits, collisions, in-level scoring, sound, and gameplay timing. Ready screens, pause, session controls, transition tunes and bonuses, reloads, level selection, and game-over restart are application behavior outside that guarantee. High score tracking, display, persistence, qualification, and initials entry are absent. The Rust game retains death/restart, level advancement, pause, and sound/speed controls as session conveniences. It presents composed sprite shapes through local SDL texture updates and plays synthesized speaker edges. Input recordings replay consumed keys without expected state. Trace verification independently reexecutes those keys and compares state, events and model timing, while MAME boots original code and compares independently observed objects. Selected machine fixtures pass historically; this does not establish complete machine equivalence or cycle accuracy.

`sources/lode_runner_reveng/` vendors reference revision `113db1c16951717259c9ae5e128958b29de0634d`, including provenance and its CC BY-SA license. Root Cargo builds the `loderunner` application/library in `src/`, the observation library in `src/trace/`, and the MAME validation library in `src/mame/`. Gameplay files are flat in `src/`; keyboard and speaker interfaces live in `src/devices/`; integration tests live in `tests/`. Only the latest game implementation is retained.

Make drives incremental Cargo builds, producing `target/release/loderunner`. Checks run formatting, Clippy, then tests. `mostlyclean` removes compiler intermediates while preserving the release executable; `clean` removes Cargo outputs too. Neither removes source assets, traces or recordings.

Execution, storage, and initialization
--------------------------------------

The game executes native gameplay rules without interpreting 6502 instructions. Counters retain byte wrapping where gameplay depends on it; closed domains use enums. Score uses a bounded decimal value with modulo-100,000,000 addition and displays its lower seven digits.

Build.rs converts original 256-byte level sectors and executable sprite tables into native assets under Cargo OUT_DIR, tracking every input with rerun-if-changed. Runtime storage indexes complete generated sectors; sprites contain ten-bit rows, whole 110-bit masks and fixed setup-cost metadata. The reference remains authoritative and Cargo regenerates derived assets incrementally. There are no disk delays or controller emulation. Decoding visits rows top to bottom and columns left to right, consuming each low nibble before its high nibble. Tile values 10 through 15 become empty; only the first 224 bytes describe the 28 by 16 playfield.

Initialization visits rows bottom to top and columns right to left. The first encountered player survives; other player markers disappear. Guards receive slots 1 through 5 in the same traversal; extras disappear. At most 45 hidden ladders are retained in allocation order and removed from both logical maps. Accepted actor markers occupy the active map only. Gold remains in both maps until collection. The game composes Foreground and Background shapes in the same order, followed by status text. No player is an initialization error. Initial rendering costs are outside the initial virtual-clock origin.

The native session decodes and validates every sector once into a `Level` with tiles, the last player marker, and the wrapping gold count. Initial load and reload consume these validated levels without parsing storage or repeating discovery. Configuration embeds the full sector list, starting index, and whether levels wait for a starting key. The original configuration contains all 150 boards. Reloading after death or completion retains the virtual clock, speaker history, sound preferences, score, lives, guard scheduler phase, and resurrection column. It increments attempt identity and resets exit availability. All reloads retain player and guard facing flags despite resetting positions and animations. Falling pitch and the pending landing-sound flag also survive every reload. A new game resets gameplay progress to the configured starting board while retaining sound preferences, facing flags, guard scheduler phase, and falling-sound state. Supported movement consumes any pending landing sound and resets falling pitch to `$20`; loading alone does neither. The death tune's final empty sound call advances falling pitch once when falling sound remains active.

Devices and graphics
--------------------

Game owns a composed Scene and a Display that retains the selected Foreground/Background Layer, scene-refresh flags, and the simple RGB cache. Scene supplies visible ink and player-contact data. The SDL host owns Presentation, which defaults to the sibling `../crt` library pipeline and can select the simple decoder. Gameplay has no HIRES addresses, page buffers, soft switches or display-hole storage; the presentation adapter serializes scene ink at the output boundary.

The build decodes each supported sprite into a whole shape. Runtime composition uses overlay, erase and replacement rules corresponding to the original masked writes and `(foreground XOR background) AND shifted_sprite` contact. All supported writes share the high color-phase bit. The CRT adapter packs each visible row into forty seven-data-bit HGR bytes with bit seven set, preserving that blue/orange phase, and uses AppleProfile::IieNtscV1 at eight samples per carrier. Color, horizontal electrical filtering and local vertical beam overlap are supplied by `crt`. The selectable simple digital decoder preserves its original adjacent-white and parity-based artifact-color rules.

Only player redraw evaluates shape contact; guard-entry and hole-closure contact use logical occupancy independently. Sprite erasure can remove another actor's overlapping pixels, and background pixels suppress foreground overlap. Current poses alone therefore do not describe every contact-relevant state. Game owns a Scene whose ten-by-eleven local cells each retain a 110-bit background mask and a 110-bit foreground/background difference mask. Appearance operations update these masks through whole-shape Boolean rules; player contact intersects its translated animation shape with at most four nearby cells. Erasure restores background across its enclosing fourteen/twenty-one-pixel span, not just its silhouette. The scene includes status placement and visible right-edge spill. RGB presentation reads these masks without changing contact state. `sources/analysis/COLLISION.md` specifies the composition identities, ordered integration, coordinate limits and measured comparisons.

Each appearance change compares old/new Foreground and Background ink separately and marks only changed local cells in the corresponding Layer. Changing Background alone can alter contrast while leaving visible Foreground unchanged. Simple mode Display groups dirty cell runs into rectangles, expands them by one horizontal pixel for neighboring color dependencies and decodes its retained RGB cache; Presentation converts this small native picture to RGBA when presenting. In CRT mode CrtDisplay encodes only scan lines intersecting dirty cells, then the library compares timed samples and propagates electrical/optical damage. The sibling `crt/native` presenter owns either a direct GPU surface or SDL CPU fallback. GPU processing covers decoding through output encoding, with no ordinary frame readback; CPU fallback uploads only damaged CRT rectangles. Layer selection, scene reload and renderer switching refresh all source rows while retaining the CRT renderer. Window resize reconstructs existing light at the new drawable size without re-decoding. Dirty flags commit after successful native submission/presentation; pending surface retries retain their own redraw request. `sources/analysis/RENDERING.md` specifies the transaction and validation.

`CRT_BACKEND=auto` selects hardware Metal/Vulkan/Direct3D 12 where available and falls back to the regular CPU pipeline on initialization or runtime GPU failure. `cpu` forces fallback and `gpu` requires acceleration. The presenter drops GPU ownership before SDL claims the same window. Retained source signals permit CPU catch-up after deferred GPU submissions. Both simple and CRT output use the selected backend, and neither backend controls game pacing. The native adapter owns the narrow unsafe SDL surface-handle and texture-destruction operations; the game does not perform graphics interop itself.

The keyboard exposes observation and acknowledgement directly. Clearing availability retains the last code; delivery replaces the latch, including repeated delivery of the same code. Releasing a host key does not stop movement; Space supplies a stop command. A code delivered while falling or digging remains unobserved until the game polls it. Trace and recording inputs are fresh acknowledged codes, rather than host key events or repeated reads of an unchanged latch. No release record is invented.

Speaker access toggles drive at a virtual cycle. PLAY_NOTE advances countdown runs between low-counter wraps and pitch reloads, retaining each edge without instruction interpretation. Its first pitch countdown uses duration; subsequent ones use pitch. Incoming low counter affects the first duration segment. Muting retains countdown duration but saves the original three-cycle speaker-access difference. Note buffers append one-based and play last-in-first-out. Overflow reports an error rather than corrupting neighboring memory.

Live audio integrates speaker drive over globally indexed sample windows, preserving fractional-cycle boundaries across batches. Pruning retains the last preceding edge so future samples start in the correct state. SDL output applies a DC-removing filter and gain. The game submits audio and graphics once per committed interval before sleeping. Host rendering, audio conversion, and file parsing do not add emulated cycles.

Player execution
----------------

MOVE_PLAYER resets the gold-pickup collision exception. Continued digging bypasses gravity and keyboard polling. Otherwise it checks ladder and centered-rope support, then active and background support below. Falling erases the previous sprite, selects a facing-specific animation, nudges horizontal adjustment, advances vertical adjustment, and collects centered gold or transfers the active marker into the next row. Landing plays its note before keyboard observation. The note's incoming low counter is row 15 on the bottom support branch and column on other support paths.

A fresh code replaces both persistent command bytes; otherwise they persist. Vertical and dig commands precede horizontal fallback. Subcell adjustments range from 0 through 4, centered at 2. Crossing a boundary transfers the active player marker; the previous cell receives background terrain except background brick becomes active empty. Horizontal movement blocks brick, stone, and trap. Downward movement blocks brick and stone but permits trap. Nudging can collect gold at the centered position.

Sacrifice, end-game, and skip controls mark the player dead but return to the current movement dispatch. The retained command may still move or dig before the main loop observes death. The pause handler suspends that dispatch until its explicit resume boundary.

Collection removes background gold, erases its graphics, adds 250, appends six original notes, and suppresses shape-contact death for the remainder of that player call. Otherwise shape contact may kill the player. The trace attributes a collision partner only when logical contact establishes that partner; anonymous shape contact is represented by death without guessing a partner.

Digging requires a brick below the adjacent empty cell. Twelve calls update debris and brick graphics; the thirteenth completes the opening. Interruption restores the brick and erases debris. Completion does not move the player despite the original DROP_PLAYER_IN_HOLE label. It removes the active brick, retains background brick, clears both graphics images, and allocates the first free slot among 0 through 29 with timer 180. Per-cell generations identify later openings independently of reused timer slots.

Control handlers include sacrifice, end game, skip level, extra life, mute, speed adjustment, keyboard mode, and pause. Return is ignored without replacing the persistent movement command. Joystick selection codes report an explicit unsupported-device error. The SDL mapping exposes the normal keyboard controls; raw capture codes also exercise original control handlers.

Guards, holes, and exits
-----------------------

The game stores a vector of concrete guards with validated identities 1 through 5. The scheduler advances a three-phase pattern selected by guard count plus difficulty, consumes bits least-significant first, and advances the round-robin guard identity for each set bit. Each selected guard completes its state/physics/route update before the next guard sees it. A dead player aborts further guard movement.

Gravity distinguishes empty/player cells, supporting guard occupants, and background terrain. The game uses `GuardMode::Roaming`, `Carrying`, `Trapped`, and `Resurrecting`, with nonzero countdowns for the latter three. Centered pickup removes background gold and seeds a drop countdown of resurrection column plus one. Dropping decrements that countdown only at movement boundaries and retries with one when the terrain is occupied. Entering a hole drops carried gold above if possible, otherwise removes it from the remaining total. Centering inside background brick starts the trap timer and awards 75.

Route selection first handles trapped escape, then a supported route on the player's row. Otherwise it considers down, up, left columns from the farthest limit inward, and right columns from the farthest inward. Only strictly better pseudo-distance changes the choice. Horizontal distance is relative to the guard. Candidate searches preserve the original left/right stale-row-pointer asymmetry. Bottom-row search stops at row 15 instead of reproducing an out-of-map zero-page pointer-table alias read; ordinary boards with a supporting bottom floor stop earlier.

Resurrection timers update before hole timers and guard movement. The resurrection column advances modulo 28 once per ordinary round. Hole timers scan slots 30 down to zero, decrement once, draw refill stages at 20 and 10, and close at zero. Closure kills a player in the hole with an environment-contact occurrence, handles gold loss, restores brick in the active map and both graphics pages, and buries the matching guard. Burial searches empty background starting at row 1 and the current resurrection column, centers the guard, and starts resurrection time 20. Stages occur at 19 and 10; expiration retries each round until active occupancy is empty, then restores the guard and appends four notes. No empty resurrection location is an error instead of an out-of-bounds scan.

Exit revealing visits hidden ladders in reverse allocation order. Empty background becomes ladder while active occupancy remains intact. Revealed entries leave the pending list; blocked background defers an entry. Once all are processed without blockage, the original gold counter becomes 0xff. GoldProgress uses Collecting, RevealPending and Revealed states. Conversion and decrement preserve the original byte-counter wrap behavior for unusually crowded custom boards; ordinary gameplay checks named states. Exit availability indicates completion eligibility, not necessarily visibility of every ladder. A centered player on row zero completes when gold count is zero or 0xff.

Rounds and session transitions
------------------------------

A gameplay round starts before MOVE_PLAYER. Its ordered operations are player update, sound/delay, exit revealing and completion check, resurrection timers, resurrection-column advancement, hole timers, sound/delay, and scheduled guards. Completion skips the latter operations. Death stops subsequent gameplay. A committed Died or LevelCleared snapshot ends the round before the separate transition interval changes lives or actor identity.

Death loses one life and plays the descending 24-note tune, appended to any remaining notes, followed by an empty sound section. Zero lives produces GameOver. Otherwise the current board reloads. Completion increases displayed level and lives, awards fifteen increments of 100 with three notes each, and loads the next board. End of the configured board list wraps to its beginning and increases difficulty. Skip-level control advances board selection through the death transition without an ordinary life loss.

Waiting, Paused, and GameOver are explicit non-gameplay intervals with 5,000-cycle polling budgets. Waiting accepts a key and retains a movement command when appropriate; Escape resumes pause. Any game-over key starts a new game. No game movement runs during these intervals.

No high score table exists in configuration, game state, snapshots, or changes. Live play and playback ignore any existing `highscores.json` and never create or update it. Game over accepts the next key directly as a new-game request.

Observation and trace replay
----------------------------

The observer consumes committed snapshots and a transient occurrence journal; it does not simulate gameplay rules. Snapshots contain session level/attempt/phase/score/lives/exit availability, actor cell/subcell/facing/motion/action/lifecycle/carried gold, both logical terrain maps, pending hidden ladders, holes with generations. Scheduler internals, delay preferences, animation bytes, and countdown values remain execution state; visible consequences are observed. Gold identity is a location or carrier, not an invented permanent identifier.

The sole cycle-based record is interval start as a delta from the previous start. Events inside are untimed. Empty intervals remain for input addressing. A final delta closes the last interval. Net snapshot changes are atomic and canonical by identity. Occurrences are not reapplied as mutations. Episodes preserve order per subject; independent subjects sort canonically. Consecutive contact runs sort and deduplicate, while non-contact occurrences retain their order. Observed inputs retain order and observation ordinal; this port supports at most one keyboard observation, ordinal zero, per interval.

Trace format version 3 carries reference/configuration identity, initial snapshot, rounds, final duration, and final snapshot. Parsing checks domains, identities, lengths, canonical ordering, interval numbers, clock overflow, change preconditions, and the resulting terminal state. Structural validity alone is not execution validation.

Replay constructs a fresh Run from embedded configuration and compares initial identity/state. For each expected interval it injects only its observed key through the keyboard device, executes the appropriate phase, and compares the independently generated round exactly. Expected changes and occurrences never drive execution. It also compares final state and duration, rejecting the first mismatch. Delayed keyboard deliveries can be injected at their observation interval because they had no prior observable effect. Unobserved host events are intentionally absent. Same-implementation comparison has zero tolerance; later emulator cross-validation may introduce interval timing tolerance without accepting gameplay differences.

Ordinary play and input recording disable trace history before execution. `Run::last_inputs` exposes keys consumed by the newest committed interval regardless of tracing. Tracing and validation retain canonical rounds for external comparison. `--input ROUND:HEX` schedules deliveries for development through the same session path.

Startup, recording, and verification
------------------------------------

`cli::Arguments::parse` selects Live, Recording or Trace playback and resolves display, pacing, bounds, renderer and validation options. `--renderer crt` is the default; `--renderer simple` selects digital artifact output. A grouped keyboard summary prints at startup and appears in --help. The SDL window is resizable, high-DPI aware and starts at 1400×960 (5×280×192). Unmodified 1–5 keys snap native scale and Tab switches rendering modes; these commands remain available during playback and never reach the gameplay keyboard or recordings. Auto-repeat is ignored for window actions. Both modes fit a centered 280:192 picture within arbitrary drawable dimensions with black letterboxing. Snap keys use window-coordinate dimensions, while CRT reconstruction uses physical drawable pixels. No arguments starts displayed live play; `--replay FILE` defaults to display; `--verify FILE` defaults to headless. `--headless` and `--display` are exclusive. Headless live execution requires a positive `--rounds`; playback uses its stored endpoint, optionally shortened by `--rounds`. Playback rejects level or scheduled-input overrides. Input schedules reject duplicate or out-of-range intervals and codes without the high bit. MAME options require a validation workflow. `--trace FILE` and `--verify FILE` imply MAME validation; `--validate` enables it without a trace destination. `--record FILE` can accompany any mode with a separate path.

`runtime::Session::new` resolves input/output paths before execution, rejecting matching paths and symlink aliases. It loads live configuration from original level assets, or restores configuration from playback. `Run::new` validates and decodes the configured boards before SDL opens. Playback never consults or updates filesystem scores. A host polls once per interval and supplies a quit flag plus a possible key. Session chooses a recorded, trace, scheduled or live delivery, advances Run with the host presentation callback, and records consumed inputs. SDL submits sound and graphics before Run paces; headless execution submits neither and prunes unused speaker history.

Recording JSON version 1 contains `configuration`, total `rounds`, and a sparse map from zero-based interval to consumed high-bit key. Configuration embeds level sectors, starting board, and wait policy. Silent intervals need no entries, but repeated keys are retained separately. The endpoint preserves trailing silence and zero-interval sessions. Parsing requires all fields, rejects unknown fields, unsupported versions, keys outside the endpoint and invalid key codes. Playback reconstructs a fresh Run and injects keys at their original observation boundary; falling/digging deliveries can be moved to that boundary because they had no earlier observable effect. It does not compare output or gameplay state with the recording.

Trace verification checks initial source/configuration/snapshot identity, then compares each independently executed canonical round exactly, and compares final state and duration at the endpoint. It concurrently validates executed intervals against MAME. Expected changes never drive either implementation. Early host quit or a shorter bound reports incomplete verification. Outputs replace their destination after execution, including completed prefixes on failure; trace and recording paths must differ from playback and each other. Both outputs are attempted before worker results are reported. MAME startup/validation failure still makes the process fail.


Timing and fidelity limits
--------------------------

Virtual cycles come from the calibrated event model and do not depend on host execution speed. Host sleeps target absolute deadlines at nominal NTSC 1,023,000 Hz, once per completed interval. Headless execution does not sleep. `sources/analysis/TIMING.md` and `EVENT_TIMING.md` retain the original timing analysis and calibration evidence.

The original attract/demo mode, level editor, joystick devices, iris effect, and spinning game-over presentation are outside this keyboard gameplay milestone. RGB artifacts and host speaker filtering are approximations. Sound-buffer overflow and impossible resurrection boards fail cleanly. These differences remain explicit so later original-machine validation does not mistake internal replay success for original equivalence.

Event-timed port execution
-------------------------

The root `loderunner` library and executable use concrete `Board`, `Player`, `Guard`, `Position`, `Holes`, `Sound`, `Score`, `Scene`, and `Display` types. Gameplay and graphics functions never advance time or compute costs. Clock has no local advance operation, Display has no pending-cycle accumulator, and TimingInterval contains only starting/ending phase and events.

`GuardSchedule` stores three-phase update counts, not bit masks. Each selected update advances the rotating guard cursor; player death stops the remaining updates. The phase survives reloads while the cursor restarts.

`Board` stores the fixed 28-by-16 terrain and current cell contents. `Position` holds a cell plus two private alignments in the range zero through four, centered at two. Traveling across an alignment edge changes cells and restarts at the opposite edge; perpendicular centering moves one alignment toward two. Leaving an actor cell restores terrain except a dug brick becomes empty. Player and guard movement share this geometry but keep separate obstacle, collection and animation rules. PlayerFrame and GuardFrame name each animation frame and retain separate movement sequences. Their validated `Sprite` identities are used by appearance operations and the timing model. Named terrain, refill, resurrection and glyph sprites keep numeric asset identities at the appearance boundary. `paint_cell`, `overlay_cell` and `erase_cell` convert board cells to reference coordinates; actor placement retains the uneven alignment geometry. Position::half_x_and_pixel_y explicitly returns horizontal half-pixels and vertical pixels. Shared asset decoding is separate from whole-shape appearance updates and RGB presentation.

`Game::play_round` is the gameplay execution path. It updates the player, stops for death or a suspended phase, plays sound, reveals eligible exits, and tests completion. An ordinary continuing round updates resurrection timers, advances the resurrection column, updates holes, plays sound again if the player survives, then updates scheduled guards. It commits a death phase after the responsible stage completes. `Run::step_with_checkpoint` supplies a keyboard delivery, calls `advance_phase`, records terminal/input work, commits the model interval, submits output, paces and records the trace boundary in that order. `advance_phase` dispatches gameplay and death/completion transitions directly; all other phases observe the latch once and execute one bounded menu poll. Capture and replay use that same Run path; the native port has no separate guard-free simulator.

The player owns its alive flag, collected-gold exception, persistent `Command`, and optional `Digging`. A supported update lands and observes input before dispatching `Stop`, `Move(Direction)`, or `Dig(DigSide)`. Gravity and continued digging bypass observation. Named Control values decode raw input codes at the keyboard boundary. Controls retain the prior command unless a normal command key replaces it; sacrifice still executes that command, while pause suspends it. Movement runs eligibility, erase, perpendicular centering, travel, collection and animation/draw once for all four directions. The original command and horizontal-fallback bytes receive the same values on supported keyboard paths, so one command preserves their behavior.

`Digging` uses one validated chronological stage from zero through twelve for either side. Twelve updates draw directional debris and progressive brick sprites; the thirteenth queues its final note, redraws the player and opens the hole without moving the actor. Starting a dig clears the persistent command. Missing brick cancels without restoration; an occupied adjacent cell restores the brick and erases the previous debris, if any. Gold checks during horizontal/vertical centering retain their execution order.

Guard mode determines whether an update waits, shakes, attempts escape, falls, or chooses a route. A trapped update decrements its release countdown; values at least thirteen wait and values seven through twelve shake. Values one through six attempt movement without gravity. Expiring the countdown returns to roaming; a blocked upward escape extends a still-positive countdown. Resurrection is a separate mode that suppresses scheduled movement while round-based timer updates draw its appearance stages. Route selection is an immutable board query in `routing.rs`. It returns an optional direction and whole-search extents. Typed ranks prefer the player row, then rows above, then rows below; distance breaks ties within each class and equal ranks keep the first candidate. Search order is current column down/up, left columns from the far edge, then right columns from the far edge. A non-rope left neighbor shifts the downward search’s right rope test down one row; at column zero that shift does not happen. Movement checks obstacles separately from same-row pursuit.

`Holes` contains thirty optional records in allocation order, each carrying its cell, nonzero remaining lifetime and generation. It allocates the first free entry and refills in reverse order. Generation counters are per cell and increment only on successful timer allocation. An opening made while all timers are occupied remains untracked, matching original behavior. `Sound` is a last-in-first-out stack of complete notes capped at 127; `append_notes` fails atomically on overflow. Playback uses the stack length before popping as the note's incoming low counter. `Score` uses decimal points directly, wraps at eight digits and draws the same seven sprite digits.

Reloads replace board-local state in place, resetting actor positions, animation, commands and dig state while retaining player facing, guard scheduler phase and a five-identity facing history in Game. The history includes identities absent from the current board, so a smaller guard roster does not erase direction needed by a later larger roster. New-game restarts retain this history too. Existing falling-sound, score/life/session and timing-journal preservation rules apply unchanged.

At interval entry, Run records the start cycle and clears the Clock work collector. Clock owns both event counts and pending draws; Display owns only presentation state. Counts describe executed gameplay work. Ordered `Work` records describe draws (`DrawKind`, sprite and position), notes (enabled, pitch, duration and incoming low counter), and sound-section boundaries (buffered duration/period, falling, or idle period). Appearance helpers retain original rendering inputs rather than deriving a duration; native dirty-region decoding and SDL uploads add no model events. `play_note` records a note without touching the speaker. `play_sound_section` flushes pending graphics work, records its beginning, applies note-stack/falling-pitch state changes, records the note if any, and records its ending. Landing notes precede subsequent player graphics. Final graphics work flushes at interval completion.

The model reads per-sprite setup costs generated at build time and computes placement costs with whole-sprite arithmetic, including the vertical lookup boundaries and seven-pixel alignment. No runtime sprite-plane or scanline-cost loop remains. It evaluates the fixed graphics and sound terms once per interval and adds calibrated event corrections. Reference note synthesis lives in `sound.rs`; it preserves the audible counter behavior without dictating gameplay control flow. Its only duration path is the sum of terms, rounded once and bounded below by zero and the sound work's duration. No phase reads a legacy cost. Poll events carry the configured 5,000-cycle batch coefficient. Pause-entry events carry a correction calibrated against a 187-cycle MAME control fixture: the correction plus the ordinary Round/Input terms equals that measured duration. GraphicsCycles and SoundCycles are internal model features, never measured journal entries.

The native model uses eighteen whole-operation features plus fixed graphics/sound terms, with no branch probes, candidate-improvement counts, or distance-class counters. `fit_port_model.py` fits training levels and chooses regularization on validation levels; test levels only report results. `port-model-report.json` records the measurement digest and errors. Held-out RMSE is 444 cycles versus 342 for the branch-heavy model and 1,699 for procedural timing; worst held-out error is 1,390 cycles (2.775%). This precision/simplicity trade-off remains within the machine-validation allowance. Captures require the same coefficients for exact replay; older captures may no longer replay under the native model.

Model audio placement follows ordered work. It preserves each note's countdown durations, speaker toggles, muting behavior and low-counter/pitch-zero wrapping. The total non-sound duration is distributed in proportion to the fixed draw-work costs; when no draws exist, it precedes the sound work. Sound-section prefixes/tails retain their fixed sound terms. This applies the fitted timing correction to gaps without changing note pitch. Every edge lies within the committed interval, and speaker drive persists across intervals and reloads. Individual speaker timestamps across a complete mixed gameplay turn follow the fitted event model.

At the end of a successful interval, Clock renders its speaker work and advances once by the model result. Run exposes only the last timing record and committed duration, even with tracing disabled; it retains no separate timing history. It submits audio and the composed display through one checkpoint, then paces against an absolute deadline at 1,023,000 Hz. SDL uses this same clock rather than a separate pacing clock. Headless execution skips sleeping. Long transition intervals render all their queued notes and final display together; intermediate per-note display checkpoints are absent.

Initial board rendering is outside the clock origin. During a reload, Clock flushes pending draws before board initialization; Clock and Speaker stay in place, including pending transition sound. Loading resets board cells, actor poses, hole timers, hidden ladders, keyboard availability, queued notes and presentation caches. It retains facing history, scheduler phase, falling sound and preferences. A new game separately resets progress, score, difficulty, resurrection column and score eligibility. Initialization paints default status counters before a second status pass displays retained progress; both passes contribute work. Score is stored once in Game and copied into the trace session only when a snapshot is taken. New initialization counts and the new board's rendering remain in the same interval journal. Thus reload rendering contributes model time instead of being discarded at the initial origin. Disk/iris/controller delays remain absent, and non-gameplay coefficients are not an exhaustive original-machine calibration.

Capture, live play, input playback and trace verification all use committed model time. There is no timing selector. Trace verification reexecutes recorded inputs and compares complete rounds and terminal state/duration directly. Trace format version 3 and the reference identity remain compatible with the MAME library; traces from older timing models can fail exact game reexecution. Historical differential runs established logical and visible-pixel equality across 40,500 intervals on all 150 boards, plus note-waveform and lifecycle comparisons. Those comparison suites and their procedural implementation are retired; portable gameplay, capture/reexecution, collision, rendering and MAME checks remain. Packed display holes are outside the native rendering contract.


Validation coverage
-------------------

`make check` runs formatting, warning-free Clippy, and portable behavioral tests. Coverage includes all 150 original boards through loading and guarded capture/reexecution, keyboard latch behavior, movement, gold, digging/refill, guards, deaths, transitions, pause, Return without a menu, and scored game over. Recording tests independently compare reconstructed traces after deferred and repeated input. CLI tests exercise real recording files through headless and dummy SDL playback, configuration independence, invalid startup combinations, source-path protection, and output preservation after MAME launch failure. Machine-decoder tests cover packed BCD, actor flags, journals, hole identities and malformed samples. `make test-render-sdl` checks actual texture readback; `make mame-validation` explicitly runs external tests.


The consolidated layout passes formatting, Clippy, portable tests, SDL streaming-texture readback, a bounded headed SDL run and the release build. On 2026-10-18, MAME 0.289 with the installed enhanced IIe ROMs passed all nine external library scenarios and the unified CLI workflow check. That CLI check records inputs and trace together, verifies the trace headlessly and with display, replays inputs with validation, checks shortened verification reporting and rejects altered timing. The local installation uses `make mame-validation ROMPATH="$HOME/mame/roms"`; packaged Lua plugin discovery is required because the validator executes in a private directory. No temporary MAME or game processes remain after these checks.


MAME interface proof of concept
-------------------------------

`sources/mame-poc/` exercises the installed Debian MAME 0.276 executable without changing MAME or the Rust port. `make mame-poc` runs Python type checks and two repeated executions of each probe. It is optional and separate from Rust checks. Raw snapshots and full process logs remain under `artifacts/mame-poc/apple2ee/`. These records are debugger capability evidence, not gameplay traces in the shared format and not port-equivalence validation.

The launcher creates isolated MAME configuration directories and starts enhanced Apple IIe (`apple2ee`) with no video/audio presentation, no throttle, and the noninteractive debugger. It uses the installed real ROMs, whose MAME audit passes; checksum failures and process warnings fail the probe. An explicit ROM search path can override MAME configuration. Headers record and verify the machine and W65C02 CPU identity. Enhanced IIe is the selected validator platform; its CMOS CPU can differ from the original NMOS timing analysis, so later interval tolerances must distinguish CPU-model effects. Three modes exercise synthetic code, a direct-loaded reference, and normal boot of the preferred 4am disk. Each mode executes twice with fresh machine configuration and must reproduce identical raw snapshots and absolute boundary cycle counts.

Lua waits at the reset-vector execution breakpoint before loading RAM or setting PC. Breakpoint creation supplies explicit condition and action strings: the 0.276 binding crashes when these are omitted. RAM inspection uses mapped reads below $C000; `read_direct_u8` cannot obtain pointers for this driver's handler-backed RAM and returns zero. The CPU's debugger SP representation includes the stack page, so a stack reset uses $01FF. A stopped CPU's `totalcycles` debugger symbol is read through a tagged printf line. Repeated cycle reads around each snapshot assert that observer work advances no CPU cycles.

Each breakpoint stops execution before the boundary instruction. A periodic Lua callback samples the stopped state, optionally delivers the next key, and resumes with `cpu.debug:go()`. Periodic scheduling affects host overhead, not boundary choice or virtual time. Persistent read/write tap objects override C000 values, clear the synthetic availability latch on either read or write to C010, and count C030 reads without replacing their hardware behavior. Fresh high-bit keyboard observations are captured; unchanged low-bit latch reads are omitted.

The synthetic loop at $1000 executes INC zero-page, LDA absolute, STA zero-page, BIT absolute, LDA absolute, and JMP absolute. Eight intervals each cost 23 cycles, increment a RAM counter, observe repeated delivery of the same key as separate inputs, retain low-bit codes after acknowledgement, and access the speaker once. Both launches produce identical parsed snapshots and timing.

The original-code probe loads the reference image at $0000-$1FFF and $5F00-$BFFF, supplies original level 1 at $9F00, establishes loader preconditions, and enters INIT_GAME_DATA at $6056. GAME_MODE zero selects the original in-memory level-copy path, avoiding disk access. Original board decoding, graphics helpers, iris, actor initialization, and scheduler setup execute. At the first $60E4 main-loop breakpoint, GAME_MODE changes to two for ordinary keyboard play. Initial loading/iris cycles are excluded from interval deltas. Gameplay instructions are not patched or translated by this probe.

MAME trace validation workflow
-------------------------------

Every validation mode starts a worker from the game's initial trace. Each committed interval publishes its canonical round, closing duration and snapshot through a channel whose send never waits for MAME. Queued intervals remain in memory until consumed, so validation lag does not alter game pacing or audio submission. Validation uses one MAME process and the same comparison path as offline library validation. Idle time awaiting intervals does not consume the machine-operation deadline. A disconnected channel drains accepted work before stopping MAME. A mismatch saves the stopped machine and closes the receiver; the game stops at its next boundary. The application saves completed trace/recording prefixes and joins the worker before reporting failure. All CLI MAME options apply to this worker. The executable defaults to `mame` on PATH. Packaged plugin modules are discovered from the resolved executable installation; `--pluginspath` overrides that path. Explicit relative executable, ROM and plugin paths resolve from the caller's directory before the child enters its isolated work directory. External Make checks accept MAME and ROMPATH installation overrides.

`src/mame/` accepts a structurally valid version-3 trace with the pinned reference source identity. Configuration contains one through 150 complete 256-byte sectors, a valid starting index, and a ready-screen wait policy. Each interval supports at most one observed high-bit key at ordinal zero. Unsupported identities, configuration or input shapes fail before executing gameplay. The library exposes `validate` for complete traces and `validate_stream` for interval producers; the root application owns startup and input playback.

The validator creates an empty, isolated work directory and extracts the playable disk from the tracked 4am archive, verifying its SHA-256. It replaces all configured level sectors and clears remaining level sectors, so the original loader detects the configured list's end through its own invalid-board path. It leaves the original score sector untouched; score routines are bypassed by the boundary adapter. The source archive is never modified. MAME's configuration, NVRAM, disk diffs, and saves use private directories within this work directory.

Firmware reset and floppy loading execute normally on enhanced IIe with W65C02. The adapter's first conditional breakpoint identifies application entry at $6000. It delivers splash Space through the keyboard device. At INIT_GAME_DATA, it sets configured displayed level and disk index and applies the approved `fixed-v2` initialization once: player-facing $05, guard-facing $0C91 through $0C95, and guard scheduler phase $64 become zero; falling-pitch counter $A4 and landing-sound flag $9B become $20. A nonzero $9B means no pending landing sound, corresponding to native initial false state. These values eliminate loader residue and are not reapplied after death, completion, or new game. The optional original-initialization mode leaves residue intact and is expected to expose incompatible initial state when it matters.

The initial snapshot occurs at ready cursor $8700 when waiting is configured, or at main-loop entry $60E4 after automatic keyboard-mode Ctrl+K otherwise. Startup input observations and source-path signals are discarded before this initial gameplay snapshot. After later loading, the adapter either samples Waiting or automatically supplies Ctrl+K to bypass the ready cursor according to the same configuration. Automatic setup inputs are not recorded as user inputs. Expected initial state is compared exactly before the first trace input is delivered.

Gameplay intervals finish at the next $60E4 entry, death $613F before decrementing lives, or completion $611A before awarding score. Pause entry is sampled before waiting for another Escape, and resumption before jumping back to CHECK_FOR_INPUT. Return-menu and score-recording entries redirect the program counter to the existing RTS at RECORD_HI_SCORE_DATA_TO_DISK.end. This explicitly adapts behavior outside the core fidelity boundary without executing menu or score logic. Game over is sampled at spinning-animation entry. A new INIT_GAME_DATA resets attempt identity and observer history, including when the previous attempt was already zero.

LOAD_LEVEL increments attempt once per death/completion reload, including an invalid-board retry that wraps the disk index. New-game initialization restores the configured starting index and attempt zero. Positions, maps, and flags in every resulting sample come from MAME RAM; the adapter does not assign expected actor coordinates, tiles, scores, timers, or branch outcomes. Phase labels and interval boundaries follow executed original source paths. Non-gameplay empty polling intervals stop at a keyboard-poll instruction after at least 5,000 CPU cycles. A pending key must be observed and processed before an input-bearing interval can close. Poll thresholds use hexadecimal debugger expressions; they are CPU-cycle thresholds, not host timers.

Every stopped sample includes relative CPU cycles, independently determined phase/attempt, mapped $0000-$1FFF RAM, observed inputs, and source-path signals. C000 reads return the adapter's latch; either read or write at C010 clears its high bit while retaining its code. The first high-bit read of a delivered key records it once; multiple original reads before acknowledgement do not duplicate that observation. The validator injects only the expected interval's key. Expected changes and occurrences are never sent as execution commands or used to advance game state.

Most trace state is decoded from persistent RAM: active/background maps, player coordinates and flags, guard parallel arrays, hole coordinates/timers, pending ladder arrays, score, level, and lives. Hole timer thresholds map to Open, ClosingFirst, and ClosingSecond at greater than 20, 11 through 20, and 1 through 10. Hole generation increases when a cell reopens after disappearing from an earlier snapshot and resets with attempt/new-game identity. Named motions cannot be derived reliably from final coordinates alone, so source-path signals record selected guard, supported input dispatch, successful directional movement, and gravity. These signals maintain observer motion history without simulating routes or movement rules.

Narrow instruction anchors preserve occurrences that snapshots could miss: collection, dropping gold, landing, trapping, actor contact, and closing-hole contact. Breakpoint actions record these observations synchronously and continue execution. The shared decoder produces object subjects and occurrence journals; the canonical observer emits net changes and sorts/deduplicates contact runs under the same contract as native capture. A collision is attributed to a guard or environment cell only when the corresponding original path establishes that partner. Framebuffer death without that evidence is not assigned an invented object.

Breakpoint addresses come from `sources/analysis/apple2-symbols.json`, regenerated from the pinned assembly and assembled image. The generator handles original includes and data directives and advances instruction lengths using legal NMOS opcodes; it does not execute instructions. Unnamed occurrence anchors are unique binary patterns in bounded source regions. Ambiguous anchors fail setup. The 4am gameplay compatibility audit establishes why these source addresses apply to the external disk.

The headless debugger automatically resumes after its callback returns. Therefore sample publication and command consumption happen within the stopped callback: an atomic sample file appears, the adapter waits for the matching atomic command file, then continues or saves/exits. Repeated cycle reads around sampling assert that observer work charges no CPU time. Input-only commands contain a key and stop/save flags. The host has a bounded timeout, kills/reaps an unfinished child on error, and retains artifacts for investigation. No process remains running after validation returns.

Each fresh decoded sample enters the same canonical Observer as native capture. Logical rounds compare exact input observations, changes, and occurrence episodes; only the start delta is removed from this exact logical comparison. The current interval's expected duration is the next round's start delta or the trace's final delta. Actual duration is the difference between consecutive MAME sample cycles. Boot/setup and the first round's absolute origin offset are outside duration comparison. Consequently one timing drift does not invalidate subsequent intervals, and the last interval cannot evade timing validation.

Playing-to-Playing intervals use an allowance of absolute cycles plus an integer percentage of expected duration, defaulting to 2,000 plus 10%. Other phase pairs use a separate absolute allowance, defaulting to 20,000,000 cycles, because disk/loading/iris/presentation time is not reproduced by the port. Both are configurable. Arithmetic uses a wide accumulator to avoid overflow. These policies never relax state or event equality. Successful reports record MAME version, machine, initialization profile, selected allowances, every interval's expected/actual duration, and work path.

The first mismatch writes expected/actual difference data, immediately saves the stopped MAME machine as `failure.sta`, and records PC, cycles, phase, attempt, latch and latch-observation status in `checkpoint.json`. The custom latch is external to MAME's save-state serialization. Raw samples, input commands, the submitted trace, prepared disk, and full process output remain available. Revalidation of the preserved trace reproduces the input sequence; debugger stateload with the private disk restores the stopped machine for inspection. Structural, launch, protocol, and timeout errors return a clean diagnostic naming their artifact path; a timeout cannot guarantee a stopped save state.

The external suite validates guarded 90-interval schedules on original boards 1, 2, 10, 25, 50, 100, and 150, plus custom fixtures for falling and deferred input, digging/refill and closing-hole death, waits, pause, sound/speed controls, Return without a menu, death/restart, completion, scored game over, and game-over restart. All seven selected original boards pass the default timing allowance with exact state/event comparison. After input-only trace validation, its native pitch and landing-sound state are compared with every raw MAME sample; this guards against resetting the profile during a restart without adding execution counters to gameplay traces. Negative tests submit structurally valid false object state and false final duration and require rejection with a save state. Guard burial/resurrection, all 150 external boards, and inactivity timeouts are not exhaustively cross-validated. Original attract/editor/joystick workflows are outside the supported native port; instrumentation does not imply their equivalence.

The former `fixed-v1` profile omitted `$A4`, whose tested 4am loader residue is `$AC`, while Rust's falling pitch starts at `$20`. A supported MOVE_PLAYER call resets `$A4` before input, hiding the difference on many boards. Level 150 falls from row zero without taking that path, incrementing the byte twice per round through PLAY_SOUND. At round 43 the original counter wrapped to `$02`, yielding two pitch-one notes whose frequent speaker-loop reloads added delay: 126,735 MAME cycles versus 67,995 Rust cycles. A controlled adapter initialized `$A4` to `$20` and reduced that round to 70,595 MAME cycles, with all 90 intervals within default tolerance and a largest relative drift of 5.29%.
