Event-timed port
================

Build with `make -C port`; run `target/debug/lode-port play`. Capture with `target/debug/lode-port capture run.json --rounds 120 --input 0:cc`, then reexecute with `target/debug/lode-port replay run.json`.

Run `target/debug/lode-port play --validate-mame --trace run.json` to validate during play. A worker boots MAME and compares committed intervals using the validator's default machine, ROM search path, initialization, and timing allowances. Intervals queue in memory while the worker catches up; validation does not block gameplay pacing or audio submission. Quitting drains the queued intervals before exiting. A mismatch stops play, saves the complete port trace, and reports the validator artifact directory containing the failing prefix, difference, machine save state, and checkpoint. The complete trace may include intervals after the mismatch because validation runs behind play. MAME and enhanced Apple IIe ROMs must be installed.

`Game::play_round` expresses the gameplay order: player, sound, exit, resurrection and holes, sound, guards. Actors use cell/alignment positions, typed commands and explicit guard states. Digging follows one chronological sequence for either side; notes use a stack and scores use decimal arithmetic. Functions record counts and typed draw/note/section work; the model owns every cost calculation. Each complete interval commits one duration, schedules speaker edges, submits audio/graphics and paces against the shared clock. The [workspace notes](../NOTES.md) specify the execution flow and remaining fidelity limits.

`src/model.json` retains the calibrated gameplay coefficients and adds polling-batch and measured pause-entry terms. Graphics and sound inputs are evaluated centrally in `event_timing.rs`; they are not measured by gameplay or graphics helpers. Non-gameplay phases use this same model. Reloads include the executed new-board rendering, unlike the baseline's omitted initialization costs. Audio corrections adjust gaps while retaining note pitch/countdown behavior.

Player contact and rendering share a composed sprite scene in `collision.rs`. Two masks per cell retain background and foreground differences, including partially erased actors and missing background. Ordered overlay, erase and replacement rules preserve those effects without per-actor pixel ownership or collision-pair tables. `render.rs` decodes changed local regions into the SDL texture, with a one-pixel halo for neighboring artifact colors. It has no HIRES memory emulator. `make -C port test-collision` reproduces the shape study; [collision analysis](../sources/analysis/COLLISION.md) and [rendering flow](../sources/analysis/RENDERING.md) specify the rules and evidence.

Run `make -C port check` for portable checks, `make -C port test-render-sdl` for actual texture-upload readback, and `make -C mame-validation port-test` for original-machine validation. Differential tests compare gameplay, calibrated costs and all visible pixels across 40,500 intervals on all 150 boards. Lifecycle scenarios compare full RGB frames through both dig sequences, menus, burial/resurrection and changing guard rosters. Isolated note waveforms also match the baseline. No production dependency on `port-original/` is required.
