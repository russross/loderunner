Lode Runner port semantics
=========================

Status and boundaries
---------------------

The same-implementation gameplay trace round-trip milestone and an external MAME trace validator are implemented. The Rust ports execute keyboard gameplay with guards, digging, gold, holes, death/restart, level advancement, pause, sound/speed controls, high-score display and initials entry. The baseline displays packed hires memory; the native port presents composed sprite shapes through local SDL texture updates. Both play speaker edges. Optional traces are independently reexecuted headlessly using only recorded observed inputs. MAME boots original code and compares independently observed object state and events with those traces. Selected gameplay and transition fixtures pass; this does not establish complete original-machine equivalence or cycle accuracy. Compact recordings remain outside the implemented work.

`sources/lode_runner_reveng/` vendors reference revision `113db1c16951717259c9ae5e128958b29de0634d`, including its provenance and CC BY-SA license. Its README identifies the reconstructed cracked Apple II disk image. The downloaded checkout remains untouched outside the root repository. Root Cargo builds `trace/`, `port-original/`, `port/`, and `mame-validation/`. `port-original/` retains the procedural baseline clock and optional event-model traces. `port/` uses concrete game-state types and event timing. Gameplay files are flat in each port's `src/`, hardware lives in `src/devices/`, and integration tests live in `tests/`. Both packages share the trace contract and reference assets; `port/` depends on the baseline only in differential tests.

Make drives incremental builds. Checks run formatting, Clippy, then tests in order. `mostlyclean` removes incremental intermediates; `clean` removes Cargo build outputs. Neither removes source assets, traces, or high scores.

Execution, storage, and initialization
--------------------------------------

The baseline translates original subroutines, loops, and conditions into Rust operations on named state. Shared exits and jumps into other routines are duplicated where necessary to keep functions self-contained. Neither port executes 6502 instructions. Counters retain byte wrapping where gameplay depends on it; closed domains use enums. The baseline score retains four little-endian packed BCD pairs. The native score uses a bounded decimal value with modulo-100,000,000 addition. Both expose the same decimal score and display its lower seven digits.

Storage reads original 256-byte sectors from vendored track data for levels 1 through 150. There are no disk delays or controller emulation. Decoding visits rows top to bottom and columns left to right, consuming each low nibble before its high nibble. Tile values 10 through 15 become empty; only the first 224 bytes describe the 28 by 16 playfield.

Initialization visits rows bottom to top and columns right to left. The first encountered player survives; other player markers disappear. Guards receive slots 1 through 5 in the same traversal; extras disappear. At most 45 hidden ladders are retained in allocation order and removed from both logical maps. Accepted actor markers occupy the active map only. Gold remains in both maps until collection. The baseline builds both hires pages; the native port composes Foreground and Background shapes in the same order, followed by status text. No player is an initialization error. Initial rendering costs are outside the initial virtual-clock origin.

Configuration embeds the full sector list, starting index, whether levels wait for a starting key, and initial high scores. The original configuration contains all 150 boards. Reloading after death or completion retains the virtual clock, speaker history, sound preferences, score, lives, guard scheduler phase, resurrection column, and eligibility for high scores. It increments attempt identity and resets exit availability. All reloads retain player and guard facing flags despite resetting positions and animations. Falling pitch and the pending landing-sound flag also survive every reload. A new game resets gameplay progress and eligibility to the configured starting board while retaining sound preferences, high scores, facing flags, guard scheduler phase, and falling-sound state. Supported movement consumes any pending landing sound and resets falling pitch to `$20`; loading alone does neither. The death tune's final empty sound call advances falling pitch once when falling sound remains active.

Devices and graphics
--------------------

The baseline Hires retains all bytes of both original 8 KiB pages, including display holes. Its buffers and inverse scanline map are heap allocated; visible byte changes dirty whole scanlines. Native Game instead owns a composed Scene and an RGB Display. Scene is the only retained source of visible ink and player-contact data. Display holds one RGB cache and the selected Foreground/Background Layer. No HIRES addresses, page buffers, soft switches or display-hole storage remain in the native port.

The baseline shifts packed sprite blocks and preserves the original masked writes. It accumulates `(foreground XOR background) AND shifted_sprite` before overlay and restores background on erasure. The native port decodes each supported sprite's unshifted geometry once, then uses whole-shape overlay, erase and replacement rules. All supported sprite writes have the same high color-phase bit, so the native palette depends only on local ink, immediate horizontal neighbors and global pixel parity. Both digital decoders preserve adjacent white pixels and alternating artifact colors; neither implements analog NTSC filtering or fully accurate half-dot phase transitions.

Only player redraw evaluates shape contact; guard-entry and hole-closure contact use logical occupancy independently. Sprite erasure can remove another actor's overlapping pixels, and background pixels suppress foreground overlap. Current poses alone therefore do not describe every contact-relevant state. Game owns a Scene whose ten-by-eleven local cells each retain a 110-bit background mask and a 110-bit foreground/background difference mask. Appearance operations update these masks through whole-shape Boolean rules; player contact intersects its translated animation shape with at most four nearby cells. Erasure restores background across its enclosing fourteen/twenty-one-pixel span, not just its silhouette. The scene includes status placement and visible right-edge spill. RGB presentation reads these masks without changing contact state. `sources/analysis/COLLISION.md` specifies the composition identities, ordered integration, coordinate limits and measured comparisons.

Each appearance change compares old/new Foreground and Background ink separately and marks only changed local cells in the corresponding Layer. Changing Background alone can alter contrast while leaving visible Foreground unchanged. Display groups dirty cell runs into rectangles, expands them by one horizontal pixel for neighboring color dependencies, and decodes only those rectangles into its retained RGB cache. It uploads them into the SDL texture using the full 840-byte cache stride. An unchanged frame needs no upload or present. First presentation and a changed Layer require a full refresh; expose/size events only request copying the retained texture to the canvas. Dirty flags clear only after successful upload and canvas copy. Backbuffer retention is not assumed. `sources/analysis/RENDERING.md` specifies this transaction and its SDL readback evidence.

Keyboard reads use C000 and acknowledge through C010. Clearing availability retains the last code; delivery replaces the latch, including repeated delivery of the same code. Persistent keyboard movement is intentional: physical release does not stop movement; Space supplies a stop command. A code delivered while falling or digging remains unobserved until the game polls it. Trace inputs are fresh acknowledged codes, not host key events or repeated reads of an unchanged latch. Thus a release record is not invented for hardware that does not expose releases.

Speaker access toggles drive at a virtual cycle. PLAY_NOTE advances countdown runs between low-counter wraps and pitch reloads, retaining each edge without instruction interpretation. Its first pitch countdown uses duration; subsequent ones use pitch. Incoming low counter affects the first duration segment. Muting retains countdown duration but saves the original three-cycle speaker-access difference. Note buffers append one-based and play last-in-first-out. Overflow reports an error rather than corrupting neighboring memory.

Live audio integrates speaker drive over globally indexed sample windows, preserving fractional-cycle boundaries across batches. Pruning retains the last preceding edge so future samples start in the correct state. SDL output applies a DC-removing filter and gain. The baseline submits audio and dirty graphics at sound and transition-note checkpoints. The native port submits them once per committed interval before sleeping. Host rendering, audio conversion, and file parsing do not add emulated cycles.

Player execution
----------------

MOVE_PLAYER resets the gold-pickup collision exception. Continued digging bypasses gravity and keyboard polling. Otherwise it checks ladder and centered-rope support, then active and background support below. Falling erases the previous sprite, selects a facing-specific animation, nudges horizontal adjustment, advances vertical adjustment, and collects centered gold or transfers the active marker into the next row. Landing plays its note before keyboard observation. The note's incoming low counter is row 15 on the bottom support branch and column on other support paths.

A fresh code replaces both persistent command bytes; otherwise they persist. Vertical and dig commands precede horizontal fallback. Subcell adjustments range from 0 through 4, centered at 2. Crossing a boundary transfers the active player marker; the previous cell receives background terrain except background brick becomes active empty. Horizontal movement blocks brick, stone, and trap. Downward movement blocks brick and stone but permits trap. Nudging can collect gold at the centered position.

Sacrifice, end-game, and skip controls mark the player dead but return to the current movement dispatch. The retained command may still move or dig before the main loop observes death. Pause and high-score handlers suspend that dispatch until their explicit resume boundary.

Collection removes background gold, erases its graphics, adds 250, appends six original notes, and suppresses shape-contact death for the remainder of that player call. Otherwise shape contact may kill the player. The trace attributes a collision partner only when logical contact establishes that partner; anonymous shape contact is represented by death without guessing a partner.

Digging requires a brick below the adjacent empty cell. Twelve calls update debris and brick graphics; the thirteenth completes the opening. Interruption restores the brick and erases debris. Completion does not move the player despite the original DROP_PLAYER_IN_HOLE label. It removes the active brick, retains background brick, clears both graphics images, and allocates the first free slot among 0 through 29 with timer 180. Per-cell generations identify later openings independently of reused timer slots.

Control handlers include sacrifice, end game, skip level, extra life, mute, speed adjustment, keyboard mode, pause, and high scores. Skip and extra-life commands disable high-score qualification. Joystick selection codes report an explicit unsupported-device error. The SDL mapping exposes the normal keyboard controls; raw capture codes also exercise original control handlers.

Guards, holes, and exits
-----------------------

The baseline retains eight-element guard arrays with one-based active slots. The native port stores a vector of concrete guards with validated identities 1 through 5. The scheduler advances a three-phase pattern selected by guard count plus difficulty, consumes bits least-significant first, and advances the round-robin guard identity for each set bit. Each selected guard completes its state/physics/route update before the next guard sees it. A dead player aborts further guard movement.

Gravity distinguishes empty/player cells, supporting guard occupants, and background terrain. The baseline encodes carrying and trap progress in one signed byte. The native port uses `GuardMode::Roaming`, `Carrying`, `Trapped`, and `Resurrecting`, with nonzero countdowns for the latter three. Centered pickup removes background gold and seeds a drop countdown of resurrection column plus one. Dropping decrements that countdown only at movement boundaries and retries with one when the terrain is occupied. Entering a hole drops carried gold above if possible, otherwise removes it from the remaining total. Centering inside background brick starts the trap timer and awards 75.

Route selection first handles trapped escape, then a supported route on the player's row. Otherwise it considers down, up, left columns from the farthest limit inward, and right columns from the farthest inward. Only strictly better pseudo-distance changes the choice. Horizontal distance is relative to the guard. Candidate searches preserve the original left/right stale-row-pointer asymmetry. Bottom-row search stops at row 15 instead of reproducing an out-of-map zero-page pointer-table alias read; ordinary boards with a supporting bottom floor stop earlier.

Resurrection timers update before hole timers and guard movement. The resurrection column advances modulo 28 once per ordinary round. Hole timers scan slots 30 down to zero, decrement once, draw refill stages at 20 and 10, and close at zero. Closure kills a player in the hole with an environment-contact occurrence, handles gold loss, restores brick in the active map and both graphics pages, and buries the matching guard. Burial searches empty background starting at row 1 and the current resurrection column, centers the guard, and starts resurrection time 20. Stages occur at 19 and 10; expiration retries each round until active occupancy is empty, then restores the guard and appends four notes. No empty resurrection location is an error instead of an out-of-bounds scan.

Exit revealing visits hidden ladders in reverse allocation order. Empty background becomes ladder while active occupancy remains intact. Revealed entries leave the pending list; blocked background defers an entry. Once all are processed without blockage, gold count becomes 0xff. Exit availability indicates completion eligibility, not necessarily visibility of every ladder. A centered player on row zero completes when gold count is zero or 0xff.

Rounds and session transitions
------------------------------

A gameplay round starts before MOVE_PLAYER. Its ordered operations are player update, sound/delay, exit revealing and completion check, resurrection timers, resurrection-column advancement, hole timers, sound/delay, and scheduled guards. Completion skips the latter operations. Death stops subsequent gameplay. A committed Died or LevelCleared snapshot ends the round before the separate transition interval changes lives or actor identity.

Death loses one life and plays the descending 24-note tune, appended to any remaining notes, followed by an empty sound section. Zero lives produces GameOver or initials entry. Otherwise the current board reloads. Completion increases displayed level and lives, awards fifteen increments of 100 with three notes each, and loads the next board. End of the configured board list wraps to its beginning and increases difficulty. Skip-level control advances board selection through the death transition without an ordinary life loss.

Waiting, Paused, HighScores, Initials, and GameOver are explicit non-gameplay intervals with 5,000-cycle polling budgets. Waiting accepts a key and retains a movement command when appropriate; Escape resumes pause. Any game-over key starts a new game. Return during gameplay shows high scores; a key or five-million-cycle timeout restores background and gameplay. No game movement runs during these intervals.

High scores rank strictly by `(level, score)`, with at most ten entries. A qualifying eligible nonzero score inserts three blank initials. Letters, space, and period enter characters; digits are ignored. The cursor advances only as far as the third slot, which subsequent characters overwrite. Backspace and forward arrow move within the three slots; Return confirms. SDL loads `highscores.json` when present, otherwise the original disk table, and writes only a changed table on normal exit. Invalid files are errors. Capture and replay use the table embedded in configuration and never depend on current filesystem scores.

Observation and trace replay
----------------------------

The observer consumes committed snapshots and a transient occurrence journal; it does not simulate gameplay rules. Snapshots contain session level/attempt/phase/score/lives/exit availability, actor cell/subcell/facing/motion/action/lifecycle/carried gold, both logical terrain maps, pending hidden ladders, holes with generations, and high scores. Scheduler internals, delay preferences, animation bytes, and countdown values remain execution state; visible consequences are observed. Gold identity is a location or carrier, not an invented permanent identifier.

The sole cycle-based record is interval start as a delta from the previous start. Events inside are untimed. Empty intervals remain for input addressing. A final delta closes the last interval. Net snapshot changes are atomic and canonical by identity. Occurrences are not reapplied as mutations. Episodes preserve order per subject; independent subjects sort canonically. Consecutive contact runs sort and deduplicate, while non-contact occurrences retain their order. Observed inputs retain order and observation ordinal; this port supports at most one keyboard observation, ordinal zero, per interval.

Trace format version 2 carries reference/configuration identity, initial snapshot, rounds, final duration, and final snapshot. Parsing checks domains, identities, lengths, canonical ordering, interval numbers, clock overflow, change preconditions, and the resulting terminal state. Structural validity alone is not execution validation.

Replay constructs a fresh Run from embedded configuration and compares initial identity/state. For each expected interval it injects only its observed key through the keyboard device, executes the appropriate phase, and compares the independently generated round exactly. Expected changes and occurrences never drive execution. It also compares final state and duration, rejecting the first mismatch. Delayed keyboard deliveries can be injected at their observation interval because they had no prior observable effect. Unobserved host events are intentionally absent. Same-implementation comparison has zero tolerance; later emulator cross-validation may introduce interval timing tolerance without accepting gameplay differences.

Trace capture is optional during SDL play. Disabling it before execution avoids retaining round snapshots and journals. Headless capture accepts an explicit input schedule for development; this is not the later compact recording/playback feature. The earlier guard-free probe remains available for focused subset tests; full sessions use Run and include guards and transitions.

Timing and fidelity limits
--------------------------

In `port-original/`, virtual cycles are derived from local sound/graphics analysis and representative gameplay block budgets; they do not depend on host execution speed. Hires helpers accumulate costs, drained before sound or interval completion. Exact helper formulas, page crossings, and rounded budgets are documented in `sources/analysis/TIMING.md`. Host sleeps target absolute deadlines at nominal NTSC 1,023,000 Hz, including multiple checkpoints per round. Headless execution does not sleep.

A separate calibrated linear model estimates completed turns from executed timing events. Before an interval, Run clears Clock and graphics timing journals, held by Hires in the baseline and Display in the native port. Helpers count graphics, sound, movement attempts, animation/collision draws, gold checks, digging, score updates, guard updates/routes/search iterations and terrain probes, timers, and exits. After all work and pending baseline graphics charges finish, the journals merge with observed-input and terminal-event counts into `TimingInterval`. Sound-cycle work is counted once across notes and section/delay overhead. Graphics/sound local costs have fixed unit coefficients; selected other event counts have fitted correction coefficients. The model does not consume the legacy total-cycle budget as a factor. `sources/analysis/EVENT_TIMING.md` specifies event meanings, fitting, storage and experiment reproduction; `event-model.json` supplies coefficients and `event-model-report.json` supplies their measured evidence.

Every successful step publishes its latest event interval and calibrated estimated duration, including untraced live play. Traced runs retain intervals for alternative traces. The model applies to Playing intervals ending in Playing, Died or LevelCleared; other phase pairs retain existing estimates. Alternative traces preserve configuration, inputs, changes, occurrences and final state and replace only start deltas and the final duration. Model replay independently reexecutes input and checks both gameplay and the selected timing model. The default clock, speaker edges, checkpoint pacing and legacy replay remain unchanged. Model traces require matching coefficients for exact native replay; the CLI's `--event-model` selects the embedded calibrated set.

Calibration boots the original code with controlled level sectors and key schedules, using fixed-v2 enhanced-IIe initialization. Optional source-entry hooks record timestamped original work separately from gameplay traces. Every modeled training/validation/test interval requires exact equality for the ten shared original/native entry-count domains. Actual cycles come from complete machine boundary intervals. Factors and regularization are selected on whole held-out levels; final test levels never select coefficients. Group search followed by individual additions/removals stops when no candidate improves validation RMSE by 0.5%. Fresh unprofiled execution of selected model traces must reproduce the profiled cycle durations exactly. Disk/loading/presentation work remains outside the fitted event domain, and calibrated W65C02 timing does not establish NMOS or complete 150-board accuracy.

Sound countdown and scanline lookup costs are locally instruction-derived. Graphics loops account for alignment and indexed page crossings, with representative setup costs. Gameplay dispatch, movement, guard route scans, timer scans, and polling use rounded local budgets. They omit some caller/setup and branch-path differences. Original clock stretching, disk delays, loading/iris timing, and complete transition presentation are not modeled. Deterministic round-trip timing proves accounting consistency, not cycle accuracy against an Apple II.

The original attract/demo mode, level editor, joystick devices, iris effect, and spinning game-over presentation are outside this keyboard gameplay milestone. RGB artifacts and host speaker filtering are approximations. Sound-buffer overflow and impossible resurrection boards fail cleanly. These differences remain explicit so later original-machine validation does not mistake internal replay success for original equivalence.

Event-timed port execution
-------------------------

`port/` builds the independent `lode-port` library and executable. Its concrete `Board`, `Player`, `Guard`, `Position`, `Holes`, `Sound`, `Score`, `Scene`, and `Display` types describe game and presentation state rather than machine storage. Gameplay and graphics functions never advance time or compute costs. `Clock` has no local advance operation, Display has no pending-cycle accumulator, and `TimingInterval` contains only starting/ending phase and events. The baseline remains in `port-original/`.

`Board` stores the fixed 28-by-16 terrain and current cell contents. `Position` holds a cell plus two private alignments in the range zero through four, centered at two. Traveling across an alignment edge changes cells and restarts at the opposite edge; perpendicular centering moves one alignment toward two. Leaving an actor cell restores terrain except a dug brick becomes empty. Player and guard movement share this geometry but keep separate obstacle, collection and animation rules. Sprite selection uses named fixed data; shared asset decoding is separate from whole-shape appearance updates and RGB presentation.

`Game::play_round` is the gameplay execution path. It updates the player, stops for death or a suspended phase, plays sound, reveals eligible exits, and tests completion. An ordinary continuing round updates resurrection timers, advances the resurrection column, updates holes, plays sound again if the player survives, then updates scheduled guards. It commits a death phase after the responsible stage completes. `Run` supplies keyboard deliveries, handles menus/session transitions and commits the resulting timing/trace interval. Capture and replay use that same Run path; the native port has no separate guard-free simulator.

The player owns its alive flag, collected-gold exception, persistent `Command`, and optional `Digging`. A supported update lands and observes input before dispatching `Stop`, `Move(Direction)`, or `Dig(DigSide)`. Gravity and continued digging bypass observation. Controls retain the prior command unless a normal command key replaces it; sacrifice still executes that command, while pause/high scores suspend it. Movement runs eligibility, erase, perpendicular centering, travel, collection and animation/draw once for all four directions. The baseline command and horizontal-fallback bytes always receive the same values on supported keyboard paths, so one command preserves their behavior.

`Digging` uses one validated chronological stage from zero through twelve for either side. Twelve updates draw directional debris and progressive brick sprites; the thirteenth queues its final note, redraws the player and opens the hole without moving the actor. Starting a dig clears the persistent command. Missing brick cancels without restoration; an occupied adjacent cell restores the brick and erases the previous debris, if any. Gold checks during horizontal/vertical centering retain their execution order and timing counts.

Guard mode determines whether an update waits, shakes, attempts escape, falls, or chooses a route. A trapped update decrements its release countdown; values at least thirteen wait and values seven through twelve shake. Values one through six attempt movement without gravity. Expiring the countdown returns to roaming; a blocked upward escape extends a still-positive countdown. Resurrection is a separate mode that suppresses scheduled movement while round-based timer updates draw its appearance stages. Route selection returns an optional direction, with strict improvements to a concrete best-distance/direction pair; its search order and right-neighbor asymmetry remain unchanged.

`Holes` contains thirty optional records in allocation order, each carrying its cell, nonzero remaining lifetime and generation. It allocates the first free entry and refills in reverse order. Generation counters are per cell and increment only on successful timer allocation. An opening made while all timers are occupied remains untracked, matching the baseline. `Sound` is a last-in-first-out stack of complete notes capped at 127; bulk loading fails atomically on overflow. Playback uses the stack length before popping as the note's incoming low counter. `Score` uses decimal points directly, wraps at eight digits and draws the same seven sprite digits.

Reloads reset actor positions, animation, commands and dig state while retaining player facing, guard scheduler phase and a five-identity facing history in Run. The history includes identities absent from the current board, so a smaller guard roster does not erase direction needed by a later larger roster. New-game restarts retain this history too. Existing falling-sound, score/life/session and timing-journal preservation rules apply unchanged.

At interval entry, Run records the start cycle and clears the Clock work collector. Clock owns both event counts and pending draws; Display owns only presentation state. Counts describe executed gameplay work. Ordered `Work` records describe draws (`DrawKind`, sprite, pixel position and shift), notes (enabled, pitch, duration and incoming low counter), and sound-section boundaries (buffered duration/period, falling, or idle period). Appearance helpers retain original rendering inputs rather than deriving a duration; native dirty-region decoding and SDL uploads add no model events. `play_note` records a note without touching the speaker. `play_sound_section` flushes pending graphics work, records its beginning, applies note-stack/falling-pitch state changes, records the note if any, and records its ending. Landing notes precede subsequent player graphics. Final graphics work flushes at interval completion.

The model evaluates the fixed graphics and sound terms from these typed inputs and adds calibrated event corrections. Its only duration path is the sum of terms, rounded once and bounded below by zero and the sound work's duration. No phase reads a legacy cost. Poll events carry the configured 5,000-cycle batch coefficient. Pause-entry events carry a correction calibrated against a 187-cycle MAME control fixture: the correction plus the ordinary Round/Input terms equals that measured duration. Gameplay coefficients remain equal to the baseline's calibrated set; `port/src/model.json` holds the fork's coefficient snapshot and its added boundary terms. GraphicsCycles and SoundCycles are internal model features, never measured journal entries.

Model audio placement follows ordered work. It preserves each note's countdown durations, speaker toggles, muting behavior and low-counter/pitch-zero wrapping. The total non-sound duration is distributed in proportion to the fixed draw-work costs; when no draws exist, it precedes the sound work. Sound-section prefixes/tails retain their fixed sound terms. This applies the fitted timing correction to gaps without changing note pitch. Every edge lies within the committed interval, and speaker drive persists across intervals and reloads. Individual speaker timestamps across a complete mixed gameplay turn are model-derived rather than baseline instruction-budget timestamps.

At the end of a successful interval, Clock renders its speaker work and advances once by the model result. Run exposes the last timing record and committed duration even with tracing disabled. It submits audio and the composed display through one checkpoint, then paces against an absolute deadline at 1,023,000 Hz. SDL uses this same clock rather than a separate pacing clock. Headless execution skips sleeping. Long transition intervals render all their queued notes and final display together; intermediate per-note display checkpoints are absent.

Initial board rendering is outside the clock origin. During a reload, the old graphics journal merges before replacing devices; the old Clock and Speaker survive, including pending transition sound. New initialization counts and the new board's rendering remain in that interval's journal, followed by status rendering with retained session data. Thus reload rendering contributes model time instead of being discarded as in the baseline. Disk/iris/controller delays remain absent, and non-gameplay coefficients are not an exhaustive original-machine calibration.

Capture, live play and replay all use committed model time by default. The CLI has no timing selector or alternative-trace option. Replay reexecutes recorded inputs and compares complete rounds and terminal state/duration directly. Trace format, source/reference identity and configuration remain shared with the baseline and MAME validator. Portable checks include device/gameplay/trace suites, exact logical and visible-pixel equality across 40,500 input-driven intervals on all 150 boards, equal calibrated gameplay costs and isolated note-waveform equality. Extra lifecycle scenarios compare complete selected-layer RGB frames and occurrence traces during digging on both sides, burial/resurrection, menus and changing guard rosters. Actual SDL streaming-texture readback matches the RGB cache after local updates, layer switches and expose presentation. The event-timed port passes seven external MAME fixture groups with exact state/occurrence comparison and ordinary timing allowances, including a guard entering a hole shortly before refill and later resurrecting. Its pause-entry fixture additionally compares duration exactly. Packed display holes remain only in the baseline and are not a native rendering contract.


Validation coverage
-------------------

`make check` runs formatting, warning-free Clippy, and portable behavioral tests. Tests include all 150 original boards through loading and guarded execution, serialized full-session capture/reexecution on each board, repeated keyboard delivery, persistent motion and gravity polling, gold pickup, thirteen-call digging, hole refill, guard scheduling/carrying/resurrection, death/restart/game over, level advancement, pause/speed/mute, high-score entry, canonical contacts, and negative state/timing/configuration traces. CLI tests capture and replay real files, reject altered timing, and replay a trace produced by SDL with dummy audio/video drivers. Machine-decoder tests cover BCD ordering, actor flags, transient journals, hole identities and malformed observations. No display was available for a headed visual check.


MAME interface proof of concept
-------------------------------

`sources/mame-poc/` exercises the installed Debian MAME 0.276 executable without changing MAME or the Rust port. `make mame-poc` runs Python type checks and two repeated executions of each probe. It is optional and separate from Rust checks. Raw snapshots and full process logs remain under `artifacts/mame-poc/apple2ee/`. These records are debugger capability evidence, not gameplay traces in the shared format and not port-equivalence validation.

The launcher creates isolated MAME configuration directories and starts enhanced Apple IIe (`apple2ee`) with no video/audio presentation, no throttle, and the noninteractive debugger. It uses the installed real ROMs, whose MAME audit passes; checksum failures and process warnings fail the probe. An explicit ROM search path can override MAME configuration. Headers record and verify the machine and W65C02 CPU identity. Enhanced IIe is the selected validator platform; its CMOS CPU can differ from the original NMOS timing analysis, so later interval tolerances must distinguish CPU-model effects. Three modes exercise synthetic code, a direct-loaded reference, and normal boot of the preferred 4am disk. Each mode executes twice with fresh machine configuration and must reproduce identical raw snapshots and absolute boundary cycle counts.

Lua waits at the reset-vector execution breakpoint before loading RAM or setting PC. Breakpoint creation supplies explicit condition and action strings: the 0.276 binding crashes when these are omitted. RAM inspection uses mapped reads below $C000; `read_direct_u8` cannot obtain pointers for this driver's handler-backed RAM and returns zero. The CPU's debugger SP representation includes the stack page, so a stack reset uses $01FF. A stopped CPU's `totalcycles` debugger symbol is read through a tagged printf line. Repeated cycle reads around each snapshot assert that observer work advances no CPU cycles.

Each breakpoint stops execution before the boundary instruction. A periodic Lua callback samples the stopped state, optionally delivers the next key, and resumes with `cpu.debug:go()`. Periodic scheduling affects host overhead, not boundary choice or virtual time. Persistent read/write tap objects override C000 values, clear the synthetic availability latch on either read or write to C010, and count C030 reads without replacing their hardware behavior. Fresh high-bit keyboard observations are captured; unchanged low-bit latch reads are omitted.

The synthetic loop at $1000 executes INC zero-page, LDA absolute, STA zero-page, BIT absolute, LDA absolute, and JMP absolute. Eight intervals each cost 23 cycles, increment a RAM counter, observe repeated delivery of the same key as separate inputs, retain low-bit codes after acknowledgement, and access the speaker once. Both launches produce identical parsed snapshots and timing.

The original-code probe loads the reference image at $0000-$1FFF and $5F00-$BFFF, supplies original level 1 at $9F00, establishes loader preconditions, and enters INIT_GAME_DATA at $6056. GAME_MODE zero selects the original in-memory level-copy path, avoiding disk access. Original board decoding, graphics helpers, iris, actor initialization, and scheduler setup execute. At the first $60E4 main-loop breakpoint, GAME_MODE changes to two for ordinary keyboard play. Initial loading/iris cycles are excluded from interval deltas. Gameplay instructions are not patched or translated by this probe.

The twenty-round schedule delivers right at round zero, stop at ten, and dig left at twelve. Player state starts at column 14, row 14, adjustments 2/2, moves to column 16, and stays there through stopping and eight dig updates. Three guards move, six gold tiles initialize, and continuing digging skips keyboard polling. Both enhanced-IIe initialization methods produce 1,044,485 gameplay cycles in total, individual intervals from 40,157 to 66,737 cycles, and 200 speaker reads. They also agree at every boundary on interval duration, player position/animation, and active/background maps. This short schedule matches the prior II+ cycle totals; that does not establish identical CPU timing for all paths. Transitions, full trace mapping, timing tolerances, and mismatch diagnosis remain outside the proof of concept.

The external boot baseline is the playable Apple II disk inside `sources/Lode Runner (4am crack).zip`, with SHA-256 `71412e9b4619291a38abc3ad60e032fcc8fba12775798f8d84aeacd108aacdf6`. Extraction selects this exact member, excluding the work disk. Each disk-mode run gets a private copy whose hash must agree before and after execution. All 150 complete level sectors must match the vendored reference. Source assets in the Rust port remain the Reset Vector reference; external baseline selection does not replace them.

Disk mode begins with a conditional execution breakpoint at application entry $6000. Its condition checks the MOVE_PLAYER call at $60E4 so an earlier loader cannot be mistaken for the application. Firmware reset, floppy boot, 0boot, and loading execute normally. At entry the probe saves mapped RAM $0000-$BFFF before application initialization modifies it. Comparison checks $6000-$8FFF against the reference with exactly two allowed splash-read operand values at $6031/$6032; RESET_GAME overwrites those values before use. Scanline/coordinate tables $1A85-$1DB1 and embedded level/graphics data $9F00-$B6FF must match exactly. Distinct startup and RWTS/DOS regions are documented in `sources/analysis/4AM_COMPATIBILITY.md`.

After saving the entry image, the adapter installs its taps. At the first splash input poll $61A9 it supplies Space; at ready cursor $8700 it supplies keyboard-mode code $8B. Each one-time breakpoint is cleared before setting the next. At the first $60E4 stop, setup key observations and speaker counts are discarded and gameplay snapshots begin. This mode never writes gameplay RAM, replaces PC/registers, or patches instructions. Initial loading, menus, and iris duration precede interval zero; the observed first gameplay boundary is cycle 12,279,437 in the tested configuration.

The two initialization methods have different raw startup storage. Player-facing byte $05 begins as $00 in direct loading and $A9 after disk boot, despite matching initial sprite animation. Some initial guard-facing bytes and unused hole coordinates also differ. The first scripted player movement makes its facing agree; this does not establish equivalence for falling before a movement command. The external disk's initial high-score sector also differs. Full trace mapping must audit retained state that can affect subsequent behavior and use matching initial high scores, rather than treating unexercised differences as harmless. The proof leaves Rust gameplay unchanged and does not validate any Rust-port trace against MAME.


MAME trace validation workflow
-------------------------------

The native SDL command `play --validate-mame --trace FILE` starts a validator worker from the run's initial trace. Each committed port interval publishes its canonical round, closing duration, and final snapshot through a channel whose send never waits for the validator. Queued intervals remain in memory until consumed, so validation lag does not alter port pacing or audio submission. Validation reuses the offline comparison path and a single MAME process; idle time awaiting port intervals does not consume the host machine-operation deadline. Each received interval updates the validator's retained replayable trace before execution. A disconnected channel finishes validation after draining accepted work. A mismatch closes the receiver, saves the stopped machine through the existing failure path, and causes the SDL loop to stop at its next interval boundary. The port writes its complete trace on exit, including any intervals generated ahead of the failing comparison, and joins the worker before reporting success or failure. Playback errors also close the channel and join the worker. High scores persist only after successful playback and validation. The default validator settings apply to this mode.

`mame-validation/` accepts a structurally valid port-generated version-2 trace with the pinned reference source identity. Configuration must contain one through 150 complete 256-byte sectors, a valid starting index, and at most ten high scores. Each interval supports at most one observed high-bit key at ordinal zero. Unsupported identities, configuration, or input shape fail before executing gameplay. This executable validates traces only; it does not offer emulator-generated traces or input recording playback.

The validator creates an empty, isolated work directory and extracts the playable disk from the tracked 4am archive, verifying its SHA-256. It replaces all configured level sectors and clears remaining level sectors, so the original loader detects the configured list's end through its own invalid-board path. It writes initial high-score rows as high-bit initials, byte level, and four most-significant-first packed BCD pairs, preserving the rest of the sector and the disk marker. The source archive is never modified. MAME's configuration, NVRAM, disk diffs, and saves use private directories within this work directory.

Firmware reset and floppy loading execute normally on enhanced IIe with W65C02. The adapter's first conditional breakpoint identifies application entry at $6000. It delivers splash Space through the keyboard device. At INIT_GAME_DATA, it sets configured displayed level and disk index and applies the approved `fixed-v2` initialization once: player-facing $05, guard-facing $0C91 through $0C95, and guard scheduler phase $64 become zero; falling-pitch counter $A4 and landing-sound flag $9B become $20. A nonzero $9B means no pending landing sound, corresponding to native initial false state. These values eliminate loader residue and are not reapplied after death, completion, or new game. The optional original-initialization mode leaves residue intact and is expected to expose incompatible initial state when it matters.

The initial snapshot occurs at ready cursor $8700 when waiting is configured, or at main-loop entry $60E4 after automatic keyboard-mode Ctrl+K otherwise. Startup input observations and source-path signals are discarded before this initial gameplay snapshot. After later loading, the adapter either samples Waiting or automatically supplies Ctrl+K to bypass the ready cursor according to the same configuration. Automatic setup inputs are not recorded as user inputs. Expected initial state is compared exactly before the first trace input is delivered.

Gameplay intervals finish at the next $60E4 entry, death $613F before decrementing lives, or completion $611A before awarding score. Pause entry is sampled before waiting for another Escape, and resumption before jumping back to CHECK_FOR_INPUT. High-score display entry is sampled after its rendering and before its first keyboard poll, and exit before the corresponding jump back to input dispatch. Initials intervals finish at the next initials-cursor entry, after a character, navigation, or rejected code is processed. Return reaches GameOver at LONG_DELAY after disk persistence; unqualified game over is sampled at spinning-animation entry. A new INIT_GAME_DATA resets attempt identity and observer history, including when the previous attempt was already zero.

LOAD_LEVEL increments attempt once per death/completion reload, including an invalid-board retry that wraps the disk index. New-game initialization restores the configured starting index and attempt zero. Positions, maps, and flags in every resulting sample come from MAME RAM; the adapter does not assign expected actor coordinates, tiles, scores, timers, or branch outcomes. Phase labels and interval boundaries follow executed original source paths. Non-gameplay empty polling intervals stop at a keyboard-poll instruction after at least 5,000 CPU cycles. A pending key must be observed and processed before an input-bearing interval can close. Poll thresholds use hexadecimal debugger expressions; they are CPU-cycle thresholds, not host timers.

Every stopped sample includes relative CPU cycles, independently determined phase/attempt, mapped $0000-$1FFF RAM, observed inputs, and source-path signals. C000 reads return the adapter's latch; either read or write at C010 clears its high bit while retaining its code. The first high-bit read of a delivered key records it once; multiple original reads before acknowledgement do not duplicate that observation. The validator injects only the expected interval's key. Expected changes and occurrences are never sent as execution commands or used to advance game state.

Most trace state is decoded from persistent RAM: active/background maps, player coordinates and flags, guard parallel arrays, hole coordinates/timers, pending ladder arrays, score, level, lives, and high scores. Hole timer thresholds map to Open, ClosingFirst, and ClosingSecond at greater than 20, 11 through 20, and 1 through 10. Hole generation increases when a cell reopens after disappearing from an earlier snapshot and resets with attempt/new-game identity. Named motions cannot be derived reliably from final coordinates alone, so source-path signals record selected guard, supported input dispatch, successful directional movement, and gravity. These signals maintain observer motion history without simulating routes or movement rules.

Narrow instruction anchors preserve occurrences that snapshots could miss: collection, dropping gold, landing, trapping, actor contact, and closing-hole contact. Breakpoint actions record these observations synchronously and continue execution. The shared decoder produces object subjects and occurrence journals; the canonical observer emits net changes and sorts/deduplicates contact runs under the same contract as native capture. A collision is attributed to a guard or environment cell only when the corresponding original path establishes that partner. Framebuffer death without that evidence is not assigned an invented object.

Breakpoint addresses come from `sources/analysis/apple2-symbols.json`, regenerated from the pinned assembly and assembled image. The generator handles original includes and data directives and advances instruction lengths using legal NMOS opcodes; it does not execute instructions. Unnamed occurrence anchors are unique binary patterns in bounded source regions. Ambiguous anchors fail setup. The 4am gameplay compatibility audit establishes why these source addresses apply to the external disk.

The headless debugger automatically resumes after its callback returns. Therefore sample publication and command consumption happen within the stopped callback: an atomic sample file appears, the adapter waits for the matching atomic command file, then continues or saves/exits. Repeated cycle reads around sampling assert that observer work charges no CPU time. Input-only commands contain a key and stop/save flags. The host has a bounded timeout, kills/reaps an unfinished child on error, and retains artifacts for investigation. No process remains running after validation returns.

Each fresh decoded sample enters the same canonical Observer as native capture. Logical rounds compare exact input observations, changes, and occurrence episodes; only the start delta is removed from this exact logical comparison. The current interval's expected duration is the next round's start delta or the trace's final delta. Actual duration is the difference between consecutive MAME sample cycles. Boot/setup and the first round's absolute origin offset are outside duration comparison. Consequently one timing drift does not invalidate subsequent intervals, and the last interval cannot evade timing validation.

Playing-to-Playing intervals use an allowance of absolute cycles plus an integer percentage of expected duration, defaulting to 2,000 plus 10%. Other phase pairs use a separate absolute allowance, defaulting to 20,000,000 cycles, because disk/loading/iris/presentation time is not reproduced by the port. Both are configurable. Arithmetic uses a wide accumulator to avoid overflow. These policies never relax state or event equality. Successful reports record MAME version, machine, initialization profile, selected allowances, every interval's expected/actual duration, and work path.

The first mismatch writes expected/actual difference data, immediately saves the stopped MAME machine as `failure.sta`, and records PC, cycles, phase, attempt, latch and latch-observation status in `checkpoint.json`. The custom latch is external to MAME's save-state serialization. Raw samples, input commands, the submitted trace, prepared disk, and full process output remain available. Revalidation of the preserved trace reproduces the input sequence; debugger stateload with the private disk restores the stopped machine for inspection. Structural, launch, protocol, and timeout errors return a clean diagnostic naming their artifact path; a timeout cannot guarantee a stopped save state.

The external suite validates guarded 90-interval schedules on original boards 1, 2, 10, 25, 50, 100, and 150, plus custom fixtures for falling and deferred input, digging/refill and closing-hole death, waits, pause, sound/speed controls, high-score display, death/restart, completion, initials editing, and game-over restart. All seven selected original boards pass the default timing allowance with exact state/event comparison. The airborne-restart fixture collides with a guard moving laterally into the falling player's cell, loses five lives, and starts a new game. After input-only trace validation, its native pitch and landing-sound state are compared with every raw MAME sample; this guards against resetting the profile during a restart without adding execution counters to gameplay traces. Negative tests submit structurally valid false object state and false final duration and require rejection with a save state. Guard burial/resurrection, all 150 external boards, and inactivity timeouts are not exhaustively cross-validated. Original attract/editor/joystick workflows are outside the supported native port; instrumentation does not imply their equivalence.

The former `fixed-v1` profile omitted `$A4`, whose tested 4am loader residue is `$AC`, while Rust's falling pitch starts at `$20`. A supported MOVE_PLAYER call resets `$A4` before input, hiding the difference on many boards. Level 150 falls from row zero without taking that path, incrementing the byte twice per round through PLAY_SOUND. At round 43 the original counter wrapped to `$02`, yielding two pitch-one notes whose frequent speaker-loop reloads added delay: 126,735 MAME cycles versus 67,995 Rust cycles. A controlled adapter initialized `$A4` to `$20` and reduced that round to 70,595 MAME cycles, with all 90 intervals within default tolerance and a largest relative drift of 5.29%. This diagnosis replaced the earlier guard-search attribution. `fixed-v2` implements matching initial falling-sound state, and Rust now retains the corresponding fields across original level/game initialization boundaries.
